sung.chords_index¶

A SQLite + FTS5 index of the chords-and-lyrics corpus, read without the corpus in memory.

The corpus (sung.chords_and_lyrics.get_lyrics_and_chords_dataset()) is a ~650 MB CSV: as a DataFrame it costs about 1.1 GB per process. This module writes it once to one SQLite file (titles, artists, language, popularity, each chart zlib-compressed, and an FTS5 table of the charts’ words) and reads that file back piecemeal: the short columns for matching, the words for lyrics search, one chart at a time.

It imports only the standard library, so a web worker that serves from the index never loads pandas (thorwhalen/sung#17). Building it does load the corpus (through pandas), so run build_chords_index() once, apart from any server. Ranking and fuzzy matching are the consumer’s business (songleaf, scoreseek); this module only stores and fetches.

>>> import os, tempfile
>>> rows = [
...     (1, "The Band", "Paper Boats", "G\nPaper boats drift", "en", 3),
...     (2, "Other", "Quiet Road", "C\nquiet road", "en", 1),
... ]
>>> path = os.path.join(tempfile.mkdtemp(), INDEX_NAME)
>>> build_chords_index(path, rows=rows)["songs"]
2
>>> read_columns(path)["titles"]
['Paper Boats', 'Quiet Road']
>>> rows_with_words(path, ["boats"])
[0]
>>> print(read_chart(path, 0))
G
Paper boats drift

sung.chords_index.build_chords_index(path, *, rows=None, batch_size=5000)[source]¶

Write the index to path; return its song count, size and build time.

rows are tuples in CORPUS_COLUMNS order (default: corpus_rows(), which loads the corpus). Row n of rows is row n of the index. The file is written beside path and moved into place when complete, so a reader never sees half an index.

Return type:

dict

sung.chords_index.connect(path)[source]¶

A read-only connection to the index, closed on exit of a with block.

One connection per call is safe across threads. Raises FileNotFoundError when there is no index at path.

sung.chords_index.local_chords_and_lyrics_zip()[source]¶

Return the path of a local copy of the chords-and-lyrics zip, or None.

Looks at $SUNG_CHORDS_AND_LYRICS_ZIP first, then at where haggle keeps its downloads ($HAGGLE_ROOTDIR/zips/<owner>/<dataset>.zip, root defaulting to ~/haggle). The haggle layout is replicated rather than asked of haggle, because importing haggle imports kaggle, which authenticates against Kaggle at import time, even for a cached file.

sung.chords_index.local_chords_index()[source]¶

Return the path of a local index file, or None.

$SUNG_CHORDS_INDEX first (an error if it names no file), then INDEX_NAME beside the local corpus zip (local_chords_and_lyrics_zip()). An index kept elsewhere (songleaf keeps its own under its data root) is found only through the variable, or passed by path to the readers.

sung.chords_index.rows_with_words(path, words)[source]¶

The rows whose chart contains every one of words (whole words, any case).

Words are matched as FTS5 tokens (unicode61: _ separates words, accents are kept). Tokenizing a query is the caller’s business: pass words, not a sentence. No words, no rows.

Return type:

list[int]
